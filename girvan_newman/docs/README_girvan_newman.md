# Girvan-Newman Community Detection for Steam Dataset

This implementation applies the Girvan-Newman community detection algorithm to Steam game similarity graphs generated by the dataset crawler pipeline.

## Overview

The Girvan-Newman algorithm is a hierarchical community detection method that works by iteratively removing edges with the highest betweenness centrality. This creates a dendrogram of communities, allowing you to analyze community structure at different granularity levels.

### Command Line Options

#### Basic Options
- `--edges PATH` - Path to edges CSV file (supports .gz compression)
- `--out-dir PATH` - Output directory for results (default: timestamped directory)

#### Community Detection Parameters  
- `--max-communities N` - Maximum number of community levels to detect (default: 10)
- `--min-community-size N` - Minimum community size to keep (default: 5)

#### Graph Filtering
- `--min-weight X` - Minimum edge weight/cosine similarity (default: 0.7)
- `--giant-only` - Only analyze the largest connected component
- `--kcore K` - Apply k-core filter before analysis  
- `--max-nodes N` - Maximum nodes to analyze (uses degree-based sampling)
- `--max-edges N` - Maximum edges to load (useful for testing)

#### System
- `--python PATH` - Python executable to use (default: python3)

## Understanding the Results

### Modularity Score
The modularity score measures the strength of division of a network into communities. Values typically range from -0.5 to 1.0:
- **0.3-0.7**: Strong community structure
- **0.7+**: Very strong community structure  
- **< 0.3**: Weak community structure

### Community Levels
The algorithm creates a hierarchy of communities:
- **Level 1**: Initial split (usually 2 communities)
- **Higher levels**: More granular divisions
- **Best level**: Level with highest modularity (optimal community structure)

### Interpreting Steam Game Communities

Communities in Steam game graphs often represent:
- **Genre clusters**: Games of similar genres (e.g., FPS, RPG, Strategy)
- **Publisher groups**: Games from the same publisher or development house
- **Theme clusters**: Games with similar themes (e.g., sci-fi, fantasy, horror)
- **Market segments**: Free-to-play vs premium, indie vs AAA
- **Target audience**: Casual vs hardcore, single-player vs multiplayer

## Algorithm Details

### Girvan-Newman Process
1. Calculate betweenness centrality for all edges
2. Remove the edge(s) with highest betweenness centrality
3. Recalculate betweenness centrality
4. Repeat until desired number of communities or convergence

### Computational Complexity
- **Time**: O(m³) where m is the number of edges
- **Space**: O(n + m) where n is the number of nodes

### Scalability Considerations
For large graphs (>1000 nodes):
- Use `--max-nodes` to sample high-degree nodes
- Apply `--kcore` filtering to focus on dense regions
- Use `--giant-only` to analyze the main component
- Consider using pre-filtered edges (e.g., `edges_top100.csv.gz`)

## Troubleshooting

### Common Issues

**Out of Memory**
- Reduce graph size with `--max-nodes` and `--max-edges`
- Apply stronger filtering with `--kcore` and `--min-weight`

**Slow Performance**
- Use `--giant-only` to focus on main component
- Sample edges with `--max-edges` for testing
- Reduce `--max-communities` if only interested in main divisions

**No Communities Found**
- Lower `--min-weight` threshold
- Reduce `--min-community-size`
- Check if graph is too small or disconnected
