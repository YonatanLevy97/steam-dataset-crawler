# Detailed Feature Analysis for Louvain Communities

This document explains how to interpret and use the detailed community feature analysis results generated by the Louvain community detection pipeline.

## Overview

The detailed feature analysis examines how different Steam game attributes are distributed within each community detected by the Louvain algorithm. This helps understand what makes each community distinct and coherent.

## Analysis Components

### 1. Community Assignments
**File:** `community_assignments.csv`

Maps each game (node) to its detected community:
```csv
node_id,community_id,community_size
123456,0,45
789012,0,45
345678,1,32
```

### 2. Feature Distribution Analysis
**File:** `detailed_feature_analysis.json`

For each feature and each community, shows the percentage breakdown of all possible values.

**Example Structure:**
```json
{
  "genres": {
    "community_0": {
      "Action": 65.2,
      "Adventure": 23.9,
      "Indie": 10.9
    },
    "community_1": {
      "Strategy": 78.1,
      "Simulation": 21.9
    }
  }
}
```

### 3. Summary Tables
**Files:** `feature_summary_*.csv`

Readable tables showing the top characteristics of each community:

**Example - Genre Summary:**
```csv
Community,Size,Top_Genre,Percentage,Second_Genre,Percentage,Third_Genre,Percentage
0,45,Action,65.2,Adventure,23.9,Indie,10.9
1,32,Strategy,78.1,Simulation,21.9,,
```

## Feature Categories

### Single-Value Features
Features where each game has exactly one value:

**Supported Features:**
- `initial_price` - Game's launch price
- `metacritic_score` - Review score (if available)  
- `required_age` - Age rating requirement
- `release_date` - Launch date (year)
- `is_free` - Free-to-play status
- `label_dead_binary` - Game status (Dead/Alive)
- `windows`, `mac`, `linux` - Platform support

**Analysis Method:** Direct percentage calculation within each community

### Multi-Value Features
Features where games can have multiple values (comma-separated):

**Supported Features:**
- `genres` - Game genres (Action, RPG, Strategy, etc.)
- `publishers` - Publishing companies
- `developers` - Development studios
- `tags` - User-generated tags
- `categories` - Steam categories (Single-player, Multiplayer, etc.)

**Analysis Method:** Each value is counted independently (games can contribute to multiple categories)

## Interpretation Guide

### Understanding Percentages

**Single-Value Features:**
```json
"is_free": {
  "community_0": {
    "True": 25.0,
    "False": 75.0
  }
}
```
- 25% of games in community 0 are free-to-play
- 75% are paid games
- Percentages sum to 100%

**Multi-Value Features:**
```json
"genres": {
  "community_0": {
    "Action": 80.0,
    "Adventure": 40.0,
    "RPG": 20.0
  }
}
```
- 80% of games in community 0 have "Action" genre
- 40% also have "Adventure" genre  
- 20% also have "RPG" genre
- Percentages can exceed 100% (games can have multiple genres)

### Identifying Community Themes

**High Coherence Example:**
```json
"community_5": {
  "genres": {"Indie": 95.2, "Platformer": 85.7, "Adventure": 42.9},
  "tags": {"Indie": 90.5, "2D": 81.0, "Pixel Graphics": 76.2},
  "initial_price": {"$9.99": 38.1, "$4.99": 23.8, "$14.99": 19.0}
}
```
**Interpretation:** Indie platformer community with consistent pricing

**Low Coherence Example:**
```json
"community_8": {
  "genres": {"Action": 35.0, "Strategy": 30.0, "RPG": 25.0, "Simulation": 20.0},
  "publishers": {"Various Publisher 1": 15.0, "Various Publisher 2": 12.0}
}
```
**Interpretation:** Mixed community, may need higher resolution parameter

### Quality Indicators

**Strong Communities:**
- One dominant feature value (>60% for single-value, >80% for multi-value)
- Consistent themes across multiple features
- Clear differentiation from other communities

**Weak Communities:**
- Uniform distribution across feature values
- No dominant characteristics
- Similar patterns to other communities

### 3. Identify Strong Patterns
```python
def find_dominant_features(analysis, community_id, threshold=0.6):
    """Find features with strong patterns in a community."""
    strong_patterns = {}
    
    for feature, communities in analysis.items():
        if f'community_{community_id}' in communities:
            community_data = communities[f'community_{community_id}']
            for value, percentage in community_data.items():
                if percentage > threshold * 100:  # Convert to percentage
                    strong_patterns[f'{feature}:{value}'] = percentage
    
    return strong_patterns

# Example usage
for i in range(10):  # Check first 10 communities
    patterns = find_dominant_features(analysis, i)
    if patterns:
        print(f"Community {i}: {patterns}")
```

### 4. Cross-Feature Validation
```python
def validate_community_coherence(analysis, community_id):
    """Check if community shows coherent patterns across features."""
    community_key = f'community_{community_id}'
    
    # Check genre consistency
    genres = analysis.get('genres', {}).get(community_key, {})
    top_genre = max(genres.items(), key=lambda x: x[1]) if genres else None
    
    # Check tag consistency  
    tags = analysis.get('tags', {}).get(community_key, {})
    top_tag = max(tags.items(), key=lambda x: x[1]) if tags else None
    
    # Check price consistency
    prices = analysis.get('initial_price', {}).get(community_key, {})
    top_price = max(prices.items(), key=lambda x: x[1]) if prices else None
    
    return {
        'top_genre': top_genre,
        'top_tag': top_tag, 
        'top_price': top_price
    }
```

## Troubleshooting Analysis

### Issue: No Clear Patterns
**Symptoms:**
- All feature values have similar percentages (~20-30%)
- No dominant characteristics
- Communities look very similar

**Solutions:**
1. Increase resolution parameter for more granular communities
2. Apply stronger graph filtering (higher min-weight, kcore)
3. Focus on giant component only
4. Check if metadata coverage is sufficient

### Issue: Too Many Tiny Communities
**Symptoms:**
- Many communities with <10 games
- Very specific but not meaningful patterns
- Fragmented analysis results

**Solutions:**
1. Decrease resolution parameter
2. Increase min-community-size filter
3. Use lower min-weight for more connections
4. Remove k-core filter if applied

### Issue: Missing Feature Data
**Symptoms:**
- Many "null" or "unknown" values
- Incomplete percentage breakdowns
- Limited analysis scope

**Solutions:**
1. Check metadata file completeness
2. Verify node_id matching between assignments and metadata
3. Filter analysis to features with good coverage
4. Handle missing data appropriately in interpretation

## Advanced Analysis Techniques

### Comparative Analysis
```python
def compare_communities(analysis, community_ids, feature):
    """Compare specific feature across multiple communities."""
    comparison = {}
    for comm_id in community_ids:
        key = f'community_{comm_id}'
        if feature in analysis and key in analysis[feature]:
            comparison[key] = analysis[feature][key]
    return comparison

# Example: Compare genre distributions
genre_comparison = compare_communities(analysis, [0, 1, 2], 'genres')
```

### Temporal Analysis
```python
def analyze_release_patterns(analysis):
    """Analyze release year patterns across communities."""
    release_data = analysis.get('release_date', {})
    
    patterns = {}
    for community, years in release_data.items():
        # Find dominant release periods
        sorted_years = sorted(years.items(), key=lambda x: x[1], reverse=True)
        patterns[community] = sorted_years[:3]  # Top 3 years
    
    return patterns
```

### Feature Correlation
```python
def find_correlated_features(analysis, community_id):
    """Find features that tend to co-occur in a community."""
    community_key = f'community_{community_id}'
    
    # Extract high-percentage features
    high_features = []
    for feature, communities in analysis.items():
        if community_key in communities:
            for value, percentage in communities[community_key].items():
                if percentage > 50:  # Threshold for "high"
                    high_features.append(f'{feature}:{value}')
    
    return high_features
```
